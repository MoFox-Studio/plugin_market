# MoFox Plugin Market 前端重写方案

版本：2026 年 11 月 6 日修订版

MoFox 插件市场用十九世纪报刊的报头、分栏、图版和篇目组织内容，保留原有蓝白与深蓝配色。地形、点云和技术档案的分层参考《明日方舟：终末地》，局部揭示和翻页交互参考 Xiaomi MiMo。插件分类、主题标签组与筛选沿用麦麦插件站的信息组织思路。

本文是本轮实现与验收依据。实施范围包括界面、推荐服务与数据库迁移；新增要求同步纳入：全站沿用原有品牌图标、精选每 5 秒轮播、分类与详情布局重写、真实标签主题组、全局不规则等高线与鼠标圆形揭示，以及插件市场专属的选择器、日期时间日历、悬浮提示和确认／输入对话框。尺寸、权重和时间阈值根据真实设备与数据校准。

## 1 设计方向与参考边界

首页用居中大报头与左右刊签确立刊物身份。桌面头版左侧为双行标题、搜索与用途入口，右侧为既有 MoFox 图标及其像素点云。向下先读精选作品和推荐，再按类别、主题浏览。目录以总目和用途索引引导查阅，详情以导语、署名、篇目和获取边栏构成专栏，作者主页以人物图版与作者自述开篇。

| 参考来源 | 采用的设计语言 | 在 MoFox 中的用途 |
| --- | --- | --- |
| 十九世纪报刊与雕版印刷 | 粗衬线报头、花体题字、双细线、图版题注、分栏与篇目 | 居中大报头与刊签、精选双面图录、资源总目、人物与档案专栏 |
| 终末地主页 | 分层主视觉、窄导航、章节边界、裁剪与渐隐 | 全站骨架、首页、加载页退场 |
| 终末地干员区及干员列表 | 档案式信息、大预览、编号、身份与属性分层 | 精选插件展示、插件详情、作者主页 |
| 终末地世界观区 | 点云扫描、刻度、坐标与观察框 | 头版右侧原品牌图版与全站地形探照 |
| 终末地影像区及视频列表 | 媒体与元信息联动、缩略预览、清晰播放入口 | 插件功能演示、专题内容 |
| 终末地玩法及工业知识区 | 图文错位、设备资料式分区、连续说明 | 使用场景介绍、入门教程 |
| 终末地新闻列表及详情 | 分类、日期、标题、分隔线与稳定正文宽度 | 市场公告、版本记录、README |
| 终末地及衍生页的地形纹理 | 不规则等高线、多山脊、留白与渐隐 | 全站连续地形图及探照图版，加载页引用相同的地形语言 |
| Xiaomi MiMo | 大字与细线、连续栏目、编号目录、鼠标揭示、局部翻转 | 首页排版、精选交互、更新与开发者入口 |
| 麦麦插件站的信息组织 | 类别、常用主题标签组、筛选的分层关系 | 插件目录与首页发现入口；不引入其视觉或地图 |

插件目录参考麦麦插件站的信息组织方式：用类别建立用途索引，以主题组帮助发现具体标签，再用筛选条件缩小结果。MoFox 保持自己的配色、字体、构图与组件，不复用麦麦插件地图、节点布置、列表地图联动、页面视觉、样式或代码。等高线的视觉依据来自终末地，作为装饰材质，不把插件目录转换为地形数据地图。

点云以头版右侧图版中的原 MoFox 图标为采样来源，等高线构成全站可滚动的地形材质。首页刊末偶尔附一枚稀有藏印，抽中时可从印记旁打开完整图录。重要文字、搜索、下载入口及兼容条件使用正常 HTML 内容，保持可选中、可访问和可搜索。

## 2 视觉系统

### 2.1 配色

继续使用项目现有色板，不引入终末地的荧光黄作为新主色，也不将 MiMo 的黑白反转机械套用于所有页面。

| 角色 | 现有颜色 | 使用规则 |
| --- | --- | --- |
| 浅色页面背景 | `#fafbff` | 首页、目录、阅读区与工作台底色 |
| 内容表面 | `#ffffff` | 卡片、表单、菜单、对话框 |
| 主蓝 | `#26a8f1` | 选中、聚焦、主视觉与加载轨道 |
| 深蓝 | `#0f87cf`、`#0a5fa0` | 链接、小字强调和需要对比度的操作 |
| 深色背景 | `#0a1220` | 深色主题、局部媒体与点云区域 |
| 主文字 | `#0b1220` | 浅色模式的标题与正文 |
| 辅助色 | 原有 mint、lemon、coral | 成功、提醒、错误等语义状态 |

所有组件引用设计变量。保留双主题，在页面初始化时应用已保存或系统主题，避免加载页和正文出现明暗闪烁。两种主题分别校准文本、边框和遮罩透明度。

### 2.2 排版与几何

报头和大标题由本地 WOFF2 字体排印。Playfair Display 800 负责拉丁字母的粗衬线报头，Pinyon Script 400 负责短题字、签名和图版题注。中文标题使用 Noto Serif SC 800 制作的 `MoFox Editorial SC` 本地子集，子集以外的汉字依次回退到系统中文衬线字体。西文字体通过 Fontsource 随构建打包，三款字库采用 `font-display: swap`，页面可先显示后备字体。字体许可随项目分发。

字号按报头、栏目、条目、署名和注释依次递减。报头与章节边界用双细线，色彩沿用现有深墨、品牌蓝和纸白。正文建议 14–16px，档案导语和阅读段落适当放大，版本号与技术字段使用等宽字。搜索、按钮和表单采用界面字体，移动输入控件至少 16px。花体仅用于短装饰，导航与操作保留中文名称。

桌面采用窄导航轨道与内容主舞台；展开后可看到完整栏目文字。顶部保持搜索、账户及通知入口。移动端使用紧凑顶栏和明确菜单，不强行压缩桌面侧栏。

全站按 8px 基础间距组织，局部用 4px 微调。容器以直角或 0–6px 小圆角为主；头像、扫描环和状态点保留圆形。使用细边框、留白与背景层级划分信息，重阴影只用于真正浮起的弹层。

全局等高线是一张沿文档坐标延伸的原创地形图。`surveyContours` 在统一的坐标和高度间隔上采样确定性地形，以 marching squares 提取等高线，生成粗细两级 SVG 曲线。相邻分段共用边界采样，山脊可连续跨过分段边缘。同一视口尺寸和文档滚动位置始终对应相同的地形。

`AppShell` 挂载一个地形视口。`useSurveyWorld` 读取原生 `scrollY`，`ContourField` 绘制可见分段和邻近分段，并复用已计算的路径。滚轮、触控滚动、键盘、滚动条和浏览器位置恢复均通过同一文档坐标平移图幅，返回原处可重新看见同一段山脊。桌面约半幅留白后渐入，窄屏增加留白，深浅主题分别控制透明度。背景位于内容之后，使用 `pointer-events: none` 和 `aria-hidden`，保证正文与控件清晰可用。

地形图收录 20 种编号图版，每片地图排列 4 枚，和原有大幅测绘图案一起进入探照窗。题材包括 T-80BVM、黑鸟、银河、黑洞、土星、探测器、鲸和蜻蜓等。图样和位置由页面版别与图幅序号确定，沿原路回卷可找回同组图案。彼岸花和人物藏印位于首页刊末，地图另以飞艇和纸鹤补足 20 种图版。

### 2.3 动效

| 效果名称 | 技术名称与实现方向 | 适用区域 |
| --- | --- | --- |
| 柔和边缘渐隐 | CSS `mask-image`、渐变透明度 | 首页媒体、章节衔接 |
| 鼠标圆形揭示 | 共享指针坐标、CSS 变量、圆形遮罩／`clip-path`；坐标即时更新，半径用 RAF 过渡 | 全局地形揭示与圆形反馈，精选区域的第二层内容 |
| 内容翻面 | CSS 3D Transform、Perspective、Backface Visibility | 少量精选介绍；同时提供普通按钮入口 |
| 点云扫描 | Three.js Points、BufferGeometry、ShaderMaterial | 对既有 MoFox 图标实际像素采样，原图完整保留；按需加载 |
| 连续地形图 | 文档坐标确定性采样、marching squares、可见与邻近 SVG 分段、原生滚动平移、半幅渐隐 | `AppShell` 全局背景，圆形探照揭示局部山脊与版画彩蛋 |
| 分阶段出现 | Opacity、Transform、短时间线 | 首页章节、媒体切换 |
| 列表与详情连续过渡 | 图标位置连续、轻淡入 | 路由切换，不延迟正文 |

按钮反馈约 120–180ms，内容切换约 240–400ms，精选展示约 600–800ms。减少动态效果模式取消大面积裁剪移动、点云旋转、视差及持续闪动。

全局圆形揭示使用一条共享鼠标事件流。X／Y 在指针事件中立即更新，不对位置做缓动或拖尾；移动速度只决定圆的半径，范围为 40–110px，快速移动时缩小、慢速时放大。半径缩小过渡为 80ms，恢复放大为 180ms；停止移动 75ms 后开始恢复至 110px。静止且半径稳定后停止 RAF，不保持空转动画。

圆形探照沿鼠标显露地形细节和分布在地图上的版画彩蛋。版画与等高线共用文档坐标，滚动经过插画时可在圆形窗口内看到局部，回卷到相同位置可以再次发现。进入精选图版时，同一指针坐标和半径驱动局部背印揭示，全局圆框退场。版画作为装饰，正文、操作与说明始终独立可读。触屏、粗指针、无悬停能力及减少动态效果模式关闭探照和局部动态揭示，地形随正常文档滚动。指针离开、窗口失焦或页面进入后台时撤销动态状态，卸载后移除监听与 RAF。

精选作品默认每 5 秒切换到下一项；提供暂停／继续以及前后切换。鼠标停留、键盘焦点位于精选区域、翻开档案、页面后台或精选离开视口时暂停。手动操作或恢复展示后重新计时，避免刚开始阅读就跳走。系统减少动态效果模式默认暂停自动切换，用户仍可主动开启。

### 2.4 品牌资产与专属交互组件

品牌资产统一使用原项目 `frontend/public/logo.png`，保持原始像素、比例和完整轮廓，覆盖导航、移动菜单、加载页、头版右侧图版、页脚与 favicon。头版点云仍从该图像素派生。精选作品图框使用插件自己的图标或对应主题的原创插图。原有搜索、GitHub、订阅、下载及评论 SVG 复用原路径，新功能图标沿用统一线宽和色板。

全站控件由插件市场自己的视觉系统提供，不能只改页面外壳后留下浏览器默认下拉或原生悬浮气泡：

| 组件 | 统一规范 | 交互要求 |
| --- | --- | --- |
| `MarketSelect` | 蓝色状态线、编号选项、紧凑双主题面板；筛选、个人表单、后台均使用 | 键盘方向键／首尾／字母定位，确认与取消；点击外部关闭，视口防溢出，保留原有值与表单事件 |
| `MarketDateTime` | 市场专属日期／日期时间弹层，月历、日期选择和时间输入遵循同一蓝白／深蓝视觉 | 支持键盘导航、月份切换、直接填写、确认与取消；校验实际日期、必填及最小／最大范围，保留原有表单值和事件，不擅自改变本地日期时间语义 |
| 市场悬浮提示 | 细框、品牌标记、短说明，替换 DOM `title` 气泡 | 鼠标与键盘焦点均可触发，Escape 关闭，位置跟随目标，触屏不滞留 |
| `MarketDialogHost` | 统一品牌标志、操作说明、原因输入、取消与确认按钮，替代 `window.confirm`／`window.prompt` 浏览器弹窗 | 异步返回结果，Escape 与关闭均视为取消；锁定背景滚动并管理焦点，路由或账号改变时取消旧请求，避免迟到确认执行到新页面或新身份 |
| 输入和选择状态 | 统一输入框、复选框、单选、文件入口、禁用／错误／聚焦状态 | 保留原生输入能力及可访问名称，禁止仅用颜色表达错误 |
| 菜单与反馈 | 推荐菜单、账户操作、弹窗和提示条沿用同一间距与层级 | 不被容器裁剪；能用键盘关闭；不出现多个覆盖层争抢焦点 |

分类入口要形成可浏览的用途索引、清晰的筛选工作区和已选条件摘要；不把所有分类缩成无层次的一排默认按钮。详情页重新组织身份、获取、兼容性、文档、版本与讨论的版式，章节定位与主要行动在桌面和移动端都可达。

日期日历替代浏览器原生日期选择器的外观与操作入口，仍保留表单名称、必填约束、错误反馈和可访问语义。操作对话框可使用 HTML `dialog` 的模态与焦点机制，但内容、样式及确认／输入流程由市场组件提供；不调用阻塞式浏览器确认和输入弹窗，不以自动确认代替用户决定。

## 3 页面重写范围

| 页面 | 新的阅读与操作顺序 | 必须保留的能力 |
| --- | --- | --- |
| 首页 | 报头与导读 → 搜索及品牌图版 → 插件速览 → 值得一试 → 猜你喜欢 → 用途分类与常用主题 → 最近更新 → 社区创作者 → 发布指南与刊记藏印 | 搜索、全部插件、真实类目直达、作品说明与获取、精选与推荐 |
| 插件目录 | 中文总目与页首检索 → 用途和主题索引、结果目录 → 首条通栏与其余编号条目 → 分页 | 关键词、分类、标签、来源、排序、网格／列表和条件恢复 |
| 插件详情 | 标题、导语与维护者署名 → 篇目、正文、获取栏 → 社区评分与相关推荐 | 作者、仓库、评分、评论、订阅、版本获取 |
| Skills | 技能总目与检索 → 编号结果 → 技能专栏、说明、版本与获取 | 技能列表、详情、版本、下载与评论 |
| 作者主页 | 人物图版、作者简介与关注 → 作者精选与荐语 → 全部作品目录 | 头像、背景、Bio、置顶、关注、本人编辑入口和分页 |
| 我的工作台 | 创作事务案头 → 当前账号 → 插件与版本、Skills、订阅与关注、访问令牌栏目 | 登录、发布、维护、资料修改与访问令牌管理 |
| 信箱 | 收件人及未读数 → 来信类别与收件列表 → 对应讨论、作品或公告 | 已读、全部已读、定位来源 |
| 管理后台 | 市场编辑部栏目索引 → 运行总览、待审核事项 → 对应治理列表与审计 | 现有角色权限、审核及治理功能 |
| 状态页 | 服务公报与总体检测结果 → 端点探测 → 市场数据与帮助 | 真实检测时间、检查通过数、失败说明与刷新 |
| 未找到页 | 缺页记录与请求路径 → 插件目录 → 其他栏目索引 | 404 说明及返回首页、插件或 Skill 目录的入口 |

保留现有 URL，避免已有插件链接失效。新增筛选状态写入 URL，返回上一页恢复条件和位置。管理页采用清晰紧凑的表格与表单，不放持续粒子背景。

桌面首页让 “The MoFox Gazette” 大报头居中，左刊签写“MOFOX STUDIO／社区出品”，右刊签在“PLUGIN MARKET”下显示已发布插件数，统计尚未到达时显示“插件与技能”。报头下的本版导读链接至“值得一试”“猜你喜欢”和创作者指南。左侧以“拓展边界，让灵感运行。”作双行主标题，右侧陈列 MoFox 原图与由原图像素生成的点云，题注为“图版一 · MoFox in Blue”。窄屏收束刊签和图版，为标题、搜索与触屏操作留出空间。

双行标题下直接放搜索框，提交插件名称或功能关键词后进入带 `q` 的插件目录。搜索下方以蓝色实底的“全部插件”为主操作。“按用途找插件”使用接口返回的真实分类，选定后进入带原始 `category` 键的目录，“发现技能”通往技能目录。

原数字索引的位置改为“插件速览”。从首页已加载的最近更新、精选和高评分条目中，按 `plugin_id` 去重，最多显示两个有名称的已发布插件。只有一项时显示一项，没有可用条目时收起整栏。标题打开插件档案，“说明”链接到该插件的 `#usage`，“获取”链接到 `#get`。

每次进入首页或刷新时抽取一次刊末印，总出现概率为 1%。抽中后从 20 幅藏印中等概率选一幅，即每幅在单次访问中的出现概率为 0.05%。题材涵盖彼岸花、花饰虎耳、T-80BVM、SR-71、登月舱、旅行者、韦布望远镜、银河、黑洞、Stephenson 2-18、土星、天体运行仪、鹦鹉螺、座头鲸、鮟鱇、水母、蜻蜓、鸟居、天文台与星图怀表。命中时桌面在创作者指南右侧展示印记，手机排在指南下方，点击“翻看藏印”可看当前图版的放大细节与题注。彼岸花保留右下角署名 `design by Lycoris radiata`。每次只展示抽中的一幅。未命中时指南使用完整版宽，刊末印及其按钮均不占位。

“值得一试”在桌面采用左图版、右资料，手机先展示图版，再展示资料。左栏收录 20 款原创刻线图版，每款分别绘制相呼应的正面与背印，共 40 面。例如浑天仪配行星轨道、海角灯塔配菲涅耳透镜、悬索桥配受力桁架。组件首次展示时随机取一款作为起点，随后随精选自动轮播或左右切换连续换画。桌面鼠标进入图版后，探照圆窗随指针显露对应背印的局部。图版编号与作品轮播序号各自对应所在序列。

右栏按分类、作者、完整插件名、摘要和操作依次阅读。“查看插件”、资料翻面、暂停及五秒轮播继续可用。精选作品图框与目录通栏首条、详情图版共用 `EditionArtwork`，优先采用真实图标，缺失或加载失败时按实际标签和分类显示标为“题材插图”的原创刻线图。

“猜你喜欢”紧随“值得一试”。其后依次安排“从一个用途开始”、常用主题、最近更新和社区创作者。页末创作者指南说明在插件项目中运行 `mpdt market publish` 发布，再前往创作者工作台管理作品与版本，同时提供开源社区入口。

“插件总目”和“技能总目”将检索与排序放入页首。在桌面左栏查阅用途索引，在右栏阅读当前结果和分页。网格模式按接口原始排序将本页第一项排为通栏图版，其余作品分栏编号。列表模式使用紧凑条目，同一作品在当前筛选下保持同一目录序号。目录序号由分页偏移和条目位置计算。

在当前目录点击分类、主题标签、排序、分页或视图按钮时，地址栏更新，阅读位置保留。插件与技能详情的四个篇目也在当前高度切换。新打开的章节链接、首页速览的“说明”和“获取”、指向具体评论的链接仍会定位到目标。浏览器后退或前进时优先恢复该条历史记录的位置。

插件与 Skill 详情把唯一主标题、真实导语、维护者与更新时间排为署名栏，旁边的图版列出资源标识和版本。宽屏在正文左边放概览、文档、版本、讨论四章篇目，右边放获取、兼容与评分信息。窄屏优先展示正文，主要下载操作仍可从底部抵达。文档内标题嵌入页面层级，原标题锚点继续可用。

插件的 `#usage` 优先展示有内容的 README。没有 README 时，这一节改为作者填写的插件描述或摘要，并展示可用的仓库、主页链接。两者均缺失时提供版本与兼容入口。`#get` 展示所选可获取版本，把 `mofox plugin install <plugin_id>@<version>` 和“复制”放在下载按钮旁。打开说明、进入获取栏或复制命令都不计入下载次数，只有读者明确点击下载操作时才记录对应版本。

作者页用头像、作者上传的背景或姓名首字形成独立人物图版，旁列姓名、真实简介与关注入口。公开资料缺少简介时显示空状态说明。作者置顶作品可以附作者自己的荐语。全部作品列出真实公开总数，订阅和下载明确标为本页作品统计。

个人工作台使用创作者案头布局。访客可以从账号入口进入，或先查阅案头栏目说明。登录后按身份条和工作栏目维护作品。社区信箱将来信类别说明放在收件栏旁，登录后显示当前收件人及真实未读数。状态页按服务公报编排检查结果、探测时间和刷新入口。未知地址以缺页记录列出请求路径，并提供其他栏目入口。

后台以“MoFox 市场编辑部”组织管理栏目。桌面并排放置栏目索引和工作区，窄屏可展开栏目目录。运行总览以实际待审核事项、近期活动与服务记录引导处理。子页保留治理、公告、策展与审计各自的操作，权限检查先于管理内容。

### 3.1 分类、常用主题与筛选

`CategoryIndex` 保留后台原有分类键，以用途索引呈现；`MarketTopicGroups` 在插件目录分类索引下方和首页分类入口下方组织现有 `taxonomy.tags`。主题是标签的浏览分组，不是新分类，也不是可直接提交给接口的多标签筛选。

| 常用主题 | 可纳入的现有标签键 |
| --- | --- |
| 智能对话 | `llm`、`auto-reply`、`persona` |
| 记忆知识 | `memory`、`graph`、`knowledge`、`search` |
| 群聊娱乐 | `game`、`multiplayer`、`entertainment`、`sticker`、`music` |
| 图像媒体 | `vision`、`image`、`media`、`video` |
| 效率自动化 | `schedule`、`news`、`digest`、`translation`、`i18n`、`utility` |
| 社区安全 | `moderation`、`security`、`filter` |

表中标签只有实际存在于 `taxonomy.tags` 时才显示；没有实际标签的主题隐藏。匹配分组时可忽略大小写，展示和提交使用接口返回的原始标签值，不改后台分类键、不补造标签、不显示推算的插件总数。未归入这些主题的标签继续保留在“全部标签”选择器中。

## 4 加载页面与全站加载系统

### 4.1 首屏品牌加载页

每次打开或刷新完整文档时，先呈现 MoFox 刊首图版。原 MoFox 标志在双色套准框中央，报头下方排市场名称、状态轨道与简短文案。边缘的等高线逐步着墨，套准框合拢，最后揭页进入目标内容。减少动态模式保留同样的静态图版。

加载页的布局和状态轨道只依赖首包内 HTML、SVG 和 CSS；品牌图形使用既有 `logo.png`，不以其加载完成作为退场条件，不等待视频、Three.js、网络字体或大图片。除复用的原图标外，建议新增加载器资源压缩后不超过 10KB。地形与裁剪装饰采用原创资产，不依赖参考站的图片资源。

刊首图版示意

```text
┌──────────────────────────────────────────────┐
│  MOFOX                          淡色等高线   │
│                                              │
│                 MoFox 标志                   │
│               The MoFox Gazette              │
│                 MoFox 插件市场               │
│                                              │
│            ───── 蓝色状态轨道 ─────          │
│               正在准备插件市场               │
│                                              │
│  细刻度与裁剪标记                            │
└──────────────────────────────────────────────┘
```

整页启动时，图版至少展示 2.4 秒，首个目标路由同时加载。两者都就绪后，以约 200 毫秒的揭页进入正文或目标页骨架。首个路由在 2.4 秒内就绪时，片头全长约 2.6 秒。减少动态模式同样保留 2.4 秒，然后直接切换。已确认的启动错误立即展示可操作的重试状态。

直接访问插件、Skill 或作者链接时，加载文案与目标对应，随后进入原目标；保留查询参数和锚点，不先展示首页。

### 4.2 三层加载机制

| 场景 | 显示方式 | 结束条件 |
| --- | --- | --- |
| 整页打开、刷新或再次访问 | 完整刊首图版 | 最少约 2.4 秒且外壳与首个目标路由就绪后转入正文或该页骨架 |
| 站内页面切换与历史导航 | 目标页骨架、顶部细进度条 | 当前路由的必要内容或确定的失败状态已显示 |
| 搜索、筛选、评论、推荐等局部请求 | 当前区域骨架或“正在更新” | 对应模块完成、空结果或明确错误 |

品牌片头只用于文档启动。首个目标路由已挂载、片头最短时间已到，而数据仍在读取时，进入目标页骨架。站内切换、筛选和局部重试沿用各自的进度反馈。

公开页面的正文不等待身份检查；个人按钮单独显示身份确认状态。受保护页面必须等待权限结果，不能先展示受保护内容。

现有首次使用提示与公告弹窗排在品牌加载页之后，任一时刻只显示一个需要用户处理的覆盖层。加载动画不承担用户确认，不自动勾选或接受任何声明。

### 4.3 状态与任务管理

```text
初始化 → 准备目标路由 → 主体就绪
                   ├→ 主体可用，局部继续加载
                   ├→ 加载缓慢
                   ├→ 需要登录或没有权限
                   ├→ 资源不存在
                   └→ 加载失败／离线

重试：创建新任务 → 重新准备当前目标
切换目标：取消旧任务 → 仅新任务可以更新页面
```

每次导航、筛选或重试分配独立任务编号，并用 AbortController 或请求版本阻止旧响应回填。取消操作不弹出“加载失败”。快速连续点击两个插件时，最后一次选择决定页面内容。

首页中的点云、作者头像、推荐、公告轮询，详情页中的评论和历史版本都不能无限延长全局加载。局部失败在该区域显示说明和重试，其他已就绪内容继续可用。

### 4.4 时间与真实进度

| 首版时间建议 | 行为 |
| --- | --- |
| 站内请求不足 150ms | 不额外闪现顶部进度条 |
| 超过 150ms | 显示局部骨架或不定进度轨道 |
| 首屏图版满约 2.4s | 首个路由就绪则揭页，仍未就绪则保留加载状态 |
| 等待超过约 3s | 提示“加载时间比平时长”，不伪装成成功 |
| 主脚本或首个路由约 8s 仍未就绪 | 图版提供重新加载入口，也可继续等待。稍后就绪则揭页，确认失败则立即显示错误 |
| 单次必要数据请求约 12s 无结果 | 结束本次等待，显示超时与重试 |
| 减少动态效果模式 | 静态状态替换或不超过 80ms 的淡入 |

这些阈值分别属于展示、启动和数据请求，不是叠加等待时间。不得等待所有网络请求停止才退出加载；公告轮询等后台请求不会停止。

没有可靠总量时使用不定进度，不显示随机增长到 99% 的假百分比。任务数可显示“已完成 2 / 4 项”，但不能冒充下载比例。只有总字节数与已接收字节数可靠时，才显示对应文件的真实传输百分比；传输完成与解析、安装完成分别表达。

### 4.5 失败与恢复

- 主脚本加载失败：初始 HTML 中提供不依赖 Vue 挂载的说明和刷新操作。
- API 超时或 500：展示对应接口失败，保留目标、筛选与输入内容；不误报“你已离线”。
- 404 或没有权限：结束加载并显示确定状态，不循环重试。
- 局部失败：例如评论失败，仅评论区显示重试。
- 离线：已存在有效缓存时可显示缓存与更新时间；尚未实现缓存的区域显示离线提示，不承诺离线可用。
- 恢复网络：可重试幂等读取；评论、评分、上传等写操作由用户决定是否重新提交。

骨架与真实内容预留相同尺寸。只播报必要状态变化，使用 `aria-busy`、命名清晰的进度元素和单一礼貌播报区。加载层可见时，键盘不能进入其背后的隐藏控件。路由完成后按导航意图恢复焦点；局部刷新不抢焦点。

## 5 猜你喜欢

### 5.1 模块位置与呈现

首页在运营精选之后加入“猜你喜欢”，首版每批最多 6 个插件，桌面采用 3 列 2 行，窄屏变为双列或单列。插件详情底部设置“你可能还喜欢”，排除当前插件。Skills 暂时保持独立目录，后续沿用相同推荐契约，不把两种资源直接混在一排。

推荐卡片使用全站卡片规范，展示名称、摘要、作者、版本、可信的评分及最多两条推荐理由。上方提供“换一批”和“管理推荐”，卡片菜单提供“不感兴趣”，操作后允许撤销。

“猜你喜欢”独立异步加载。主页面先可用，推荐区域保留固定尺寸骨架；失败显示“推荐暂时不可用”和重试，不能阻塞全屏加载，也不能把错误显示成“暂无推荐”。候选不足时少于 6 个，不复制条目凑数。

### 5.2 首次访问与个性化

| 用户情况 | 推荐方式 | 页面说明 |
| --- | --- | --- |
| 未登录且没有兴趣设置 | 不同分类的高分、热门和新发布插件 | “先看看热门与新上架” |
| 未登录，主动选择兴趣 | 根据本机保存的分类与标签推荐 | “根据你选择的兴趣” |
| 已登录，启用个性化 | 根据现有订阅、评分与关注作者推荐 | 显示真实命中的推荐理由 |
| 已登录但没有足够信号 | 主动兴趣或非个性化发现 | 不宣称已经了解用户偏好 |
| 关闭个性化 | 保留通用发现模块 | 明确显示非个性化推荐 |

匿名用户可选择 1–3 个兴趣分类，也可以直接跳过。首版不依赖浏览历史、停留时间或追踪脚本；无需 LLM、外部向量服务或 API key。登录后提供明确的个性化启用开关，匿名兴趣不自动并入账号。

当前项目已具备订阅、作者关注、评分、分类和标签。当前首页精选与热门属于全站榜单，不是个性化推荐。现有 `likes_count` 和 `viewer_has_liked` 来自订阅关系，不能再作为独立点赞重复计权。现有下载计数没有个人安装结果，不能推断某用户已安装或安装成功。

### 5.3 候选规则

进入候选池的插件必须处于公开发布状态，并存在可获取的有效版本。首版发现推荐默认使用稳定版本，不推荐已撤回版本。用户提供宿主版本、API 版本或平台时，服务端先校验输入格式，再复用现有兼容性逻辑筛选。现有版本匹配逻辑在部分非法版本输入下可能放行；新增接口必须拒绝非法输入或标记为未知，不能据此宣称兼容。

没有环境信息时显示“兼容性待确认”，不能标注已经兼容。插件下架、封禁、弃用或版本失效后，在返回推荐前重新校验。

默认排除当前详情插件、用户自己的或参与维护的插件、明确不感兴趣项，以及已订阅或已评分的插件。订阅更新留在订阅模块。用户可以主动标记“我已有这个”；这只代表用户声明，不声称读取了设备安装列表。

“不感兴趣”仅影响推荐，不会偷偷从用户主动搜索的结果中删掉插件。

### 5.4 首版排序

采用可解释的内容推荐：分类与标签表示插件用途，订阅、高评分和关注作者表示用户主动兴趣。分类特征权重起始为 2，标签为 1；归一化后计算相似度，避免堆砌标签抬高分数。同一插件的多个正向动作取最高信号权重，避免重复放大。

所有分量归一化到 0–1，初始排序分数为：

```text
推荐分 = 0.50 × 兴趣相似度
       + 0.15 × 作者关注
       + 0.15 × 平滑评分
       + 0.10 × 全站热度
       + 0.10 × 发布新鲜度
```

平滑评分将评分人数与全站平均值一起考虑，避免一条五星评价直接压过有充分评价的插件。可用 `(人数 × 均分 + 5 × 全站均分) / (人数 + 5)`，无评分数据时以 3 分作先验。热度对累计下载和订阅取对数并封顶；新鲜度采用最新公开版本的发布时间，避免仅修改简介就不断进入新发布推荐。

无个性化信号时改用高分、热度、新鲜度组合。任何权重均不覆盖发布状态与兼容性限制。

每批 6 个的初始多样性约束：同作者最多 2 个，同主分类最多 3 个；候选足够时覆盖至少 3 类，并保留 1 个兴趣范围外的探索项。主动设置的筛选条件属于硬限制，兴趣属于软偏好；探索项只能超出软偏好，不能越过硬筛选。用户明确限制类别或候选不足时可减少条目、逐步放宽多样性约束，但不放宽资格条件与硬筛选。

同一批次顺序稳定。点击“换一批”才获取下一批，并排除当前会话近期已展示项；返回页面恢复原批次，不反复洗牌。无更多候选时明确告知。

### 5.5 推荐理由与用户控制

推荐理由由实际命中的规则生成，例如“与你订阅的工具类插件相关”“来自你关注的作者”“最近发布”。不生成没有数据支持的理由或过度推断用户身份的描述。

“不感兴趣”排除该插件；“减少此分类”降低类别权重；两者都支持撤销。取消订阅不等于讨厌整个分类。1–2 分评分可排除该插件，但不据此否定同类所有插件。

管理推荐页面提供启用个性化、编辑兴趣、查看忽略项、恢复条目与重置偏好。匿名兴趣和忽略项建议本机保存 30 天；登录后的推荐反馈建议 90 天过期，界面明确期限。原有订阅、关注与评分保留原业务生命周期。

首版不建立服务器浏览历史，不读取搜索原文、评论内容、IP、昵称或设备指纹来推断兴趣。会话展示去重只在内存保留有限插件 ID。请求与日志避免记录兴趣正文和会话凭据。

### 6.2 推荐接口

推荐使用独立接口，不改写全站搜索的排序与结果总数：

```text
POST /api/v1/recommendations

输入：placement(home/detail)、context_plugin_id、limit、
      interests、filters、exclude_ids、environment、cursor

输出：recommendation_id、algorithm_version、mode、generated_at、
      items[plugin、recommended_version、compatibility、reasons]、next_cursor
```

`mode` 区分 personalized、contextual 和 popular。`interests` 表示软偏好，`filters` 表示用户明确选择的硬条件。登录身份只从服务端会话读取，不接受客户端指定用户 ID。输入的兴趣、筛选与排除项限制数量和长度，所有候选资格由服务端验证。

新增登录用户推荐偏好读写接口，维护启用状态、兴趣与忽略项，并支持重置；写操作沿用鉴权和同源检查。匿名偏好只保存在本机，推荐请求携带必要的分类和排除 ID，不建立持久匿名指纹。

推荐响应使用私有缓存策略，建议 HTTP `private, no-store`；服务端可短期缓存计算结果。内部 key 包含身份、偏好版本、个性化开关与 mode、placement、context_plugin_id、环境、兴趣／硬筛选／排除条件摘要、候选目录版本、算法版本与批次。匿名偏好不同的请求不能共享同一份个性化结果，首页与不同详情页也不能复用错误的上下文结果。

登录、退出、换账号、修改偏好后立即清空前端推荐状态并取消旧请求。订阅、评分、关注和治理状态变化使相关缓存失效。游标绑定身份与条件；旧身份的游标不能继续读取结果。

### 6.3 搜索与推荐分工

用户明确输入查询和选择排序时，搜索遵循该意图。“猜你喜欢”是独立栏目，不向搜索结果中插入随机探索项、不修改搜索总数，也不覆盖用户选定排序。

## 7 实施顺序

1. 建立蓝白与深蓝报刊色板、本地衬线与花体字库、标题层级及双细线规范，统一导航、选择器、日期日历、悬浮提示与操作对话框。
2. 完成品牌加载页、路由加载、局部骨架、错误与重试，再接入全部现有页面。
3. 建立居中报头、双行导读、头版搜索与分类直达、原图点云，编排精选双面图录、推荐、用途索引及页末创作者指南与稀有刊末印。重写目录、详情、Skills、作者、工作台与信箱，再统一后台编辑部、状态公报与缺页记录。
4. 接入基于文档坐标的分段连续地形图、圆形探照和版画彩蛋、既有 MoFox 原图像素派生点云，以及精选图版的局部背印揭示。
5. 新增推荐服务与偏好数据，再实现“猜你喜欢”、理由、换一批和反馈；验证冷启动及账号隔离。
6. 完成移动端、键盘、减少动态效果、慢网与失败场景验证。
